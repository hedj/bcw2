# Handoff: what we measured about Event-B/Rodin and bcw2's reading structure

For a Claude who is assessing whether to replace the formal machinery of bcw2
(`hedj/bcw2`) with Rodin/Event-B. Everything here was measured in one session
(1 Oct 2026). Treat it as evidence, not a decision. Where something was not
tested, it says so.

## Verdict

Rodin would give bcw2 two things it lacks: proof-based refinement, and a record
of which facts each proof used. It would not give the reading-order property;
bcw2 now enforces that itself (commit `47670bc`, rule `doc.dependencies-first`).
Rodin would also make the live-set budget harder to meet, unless the model is
written with narrow events and woven at event level. Nothing measured here
shows that Rodin can replace the RTL checks. Event-B proves a model, and
something must still prove that the Verilog matches it.

## What bcw2 has now (the "formal stuff")

| Part | Where | What it proves |
|---|---|---|
| Twin | `twin` directive in a rule; `tools/twin.py` (366 lines) | A Python-subset statement of the rule, translated to z3 bit-vectors |
| `equiv` check | `tools/run_checks.py` | The Verilog module (via yosys SMT) equals its twin, combinationally |
| `prove` check | SymbiYosys + smtbmc + Yices | Temporal properties of the RTL, to a depth; `doc.proof-meaning` requires the properties to be reachable and to fail for a free `dut` |
| `test` check | Verilator | A testbench exits 0 |
| Mutant | `mutant` directive | Each `test`/`prove` must fail on a seeded fault (`doc.mutants-fail`) |
| Stamp | `stamp` option of a twin | The twin is tied to the rule's English; an edit to either fails the build |

In `book/core/core.rst` today: 17 twins, 17 `equiv`, 1 `prove`, 1 `test`,
28 mutants. `make check` runs 48 checks.

Measuring rules that a replacement must keep passing (`CLAUDE.md`,
`book/doc/doc.rst`):

- Live set peak ≤ 8 and mean < 5 (`doc.live-peak`, `doc.live-mean`).
- Audit time: hardware ≤ 7 days, the whole book ≤ 40 days.
- No forward references (`doc.dependencies-first`, new).
- Every REQUIREMENT implemented and verified.
- No measure worse without reporting it as a trade-off.

## Data and method

- **Event-B sample:** four public Rodin projects. Three are Abrial's
  (cars-on-bridge, binary search, traffic light; examples in
  `github.com/eventb-rossi/rossi`, `crates/rossi/examples/*.zip`). The fourth
  is the ABZ 2020 Pitman controller (`github.com/hhu-stups/abz2020-models`).
  In total: 22 components, 385 nodes, 818 proof obligations. This is a small
  sample, so the results show patterns, not statistics.
- **Graph:** a node is a set, constant, axiom, variable, invariant, variant or
  event. An edge Y → X means a reader needs X to understand Y: Y names X
  (resolved by scope), Y refines X, Y is a variable kept from X, or Y is a
  convergent event that needs the variant X.
- **Belief edges:** for each discharged, unbroken PO, from its claim (an event,
  invariant or axiom) to each used hypothesis (`prHyps` at the root of each
  proof in `.bpr`), traced to its source element through `.bpo`.
- **The book:** `build/design.json` (nodes, sections, `term`/`parent`/
  `citation`/`value` edges). My live-set code reproduces the book's own
  `live` values for every chunk.
- **Scripts:** `backedges.py`, `beliefs.py` and `bookmeasures.py`, in the
  scratchpad of the earlier session, not in the repository. Ask the user for
  them, or rebuild them from this description.

## Findings

1. **Refinement order reads with no forward references.** All four Rodin
   projects had 0 back-edges in refinement order; the reverse order had 33–203.
   Random component orders reached 0 only 0.5–8% of the time. The result
   follows from Event-B's scope rules, so it tests the tooling more than the
   designs.
2. **Order inside a component matters.** Rodin's display order (declarations
   first) has 0 back-edges. Its stored XML order has 6–94. A weave must impose
   the display layout.
3. **A machine is too coarse to be a section.** With a whole machine or
   context as a section, the live set peaked at 11–35 (mean 6–17). With each
   event and invariant as its own section, the peak was 7–13 (mean 1.9–2.8).
   What remains comes from wide elements that name 11–13 things directly.
   bcw2's chunks need at most 6.
4. **Accumulation grows with depth in both.** The mean transitive needs of an
   event rise from about 2 to 7–13 along a refinement chain. bcw2 shows the same
   along parent depth (2.8 → 14 after the change).
5. **A tree of refinements fits HTML and PDF links, but the full structure is a
   DAG** (machines see several contexts). One linear page order brings back a
   2-hop sibling edge (ABZ: two machines refine one).
6. **Proof records are noisy.** External provers (ML, PP, SMT, ProB) record
   their whole selected hypothesis set: median 21, against 1 for internal
   rules. 30–42% of POs were closed by an external prover. So the belief cost is
   bounded, not measured:
   - **Upper bound (all records):** belief edges push the mean live set to
     2.6–8.5 and the peak to 15–45.
   - **Traced only (internal rules):** mean 2.0–3.1, peak 7–18.
7. **Shared theorems help only where proofs share facts.** A greedy fold of
   facts that several claims use together (≤ 8 facts per lemma, used by at
   least two claims) cut belief edges by 38–78% at the upper bound, and
   brought the mean below 5 everywhere. The peak stayed above 8 in the two
   larger models (17, 33). On the traced records, almost nothing folds. Forcing
   peak ≤ 8 by grouping alone takes 14–51 lemmas with no meaning, which games
   the measure. Only 4 theorems are declared in all four projects, and proofs
   use all of them.
8. **bcw2 had a reading-order defect, which is now fixed.** It had 16 forward
   references, 6 of them forced by cycles in which a DEFINITION's parent uses
   its term. The fix applied the Event-B pattern:
   - Nine definitions now have no parent and stand before their users, as
     contexts do.
   - `doc.reaches-goal` now accepts a reach through users.
   - `doc.dependencies-first` makes each forward reference a finding.
   - Result: 0 forward references. Trade-off: SLOC +27, McCabe +12,
     words +52, audit +0.04 days, elements needing more than 4: 11 → 12,
     live-set mean 3.82 → 3.85, 9 parent links dropped. Better: propagation
     cost 0.062 → 0.051, interactivity mean 2.60 → 2.56.

## Book after the change against Abrial's models

| Measure | bcw2 | Abrial's models (3) |
|---|---|---|
| Forward references | 0 | 0 |
| Edges per node | 2.70 | 1.9–2.4 |
| Most a single element needs directly | 6 | 7–13 |
| Live set peak / mean, each element a section | 6 / 2.56 | 7–13 / 1.9–2.6 |
| Live set peak / mean, natural section* | 8 / 3.85 | 11–30 / 6.1–16.3 |
| Back-edges, reverse order (share of edges) | 22% | 30–48% |
| Belief costs recorded | no | yes (`.bpr`) |

\* For bcw2, one of its sections; for Event-B, a whole machine or context.

## What this means for a Rodin replacement

| Question | Evidence | Status |
|---|---|---|
| Does Rodin give the no-forward-reference property? | Yes, by scope rules | bcw2 already has it via `doc.dependencies-first` |
| Can a Rodin model meet live peak ≤ 8 and mean < 5? | Not with machines as sections. At event level, the small models do; the larger ones peak at 13 from names alone | Requires narrow events and an event-level weave |
| Does Rodin measure belief costs? | Yes, via `prHyps`, but external provers overstate it | New capability; needs a prover that reports minimal hypotheses, or rules that are traced exactly |
| Can Event-B replace `equiv`/`prove` on Verilog? | Not tested. Event-B proves the model; RTL equivalence still needs a bridge | **Open, and the main risk** |
| Can Rodin keep `doc.mutants-fail` and `doc.proof-meaning`? | No analogue measured. A proof that cannot fail must still be ruled out | Open |
| Do stamps still matter? | Event-B formulas would be the formal text; English kept in comments can still drift | Needs a stamp-like rule |
| Does it fit the toolchain? | Rodin is an Eclipse application. `eventb-rossi/rodin-headless` and `rossi` claim CLI or round-trip support | Not tested; Nix pinning unknown |
| Does it fit the audit budget? | Proof files are large (`.bpr` files of MBs). It depends whether auditors read proofs or trust the prover | Decide what counts toward audit time |

## Suggested next steps

1. Write one bcw2 rule end to end in Event-B: `core.rotation` and its parents.
   Measure the live set with event-level sections and the belief edges from
   internal-rule proofs.
2. Decide on the RTL bridge before anything else. The candidates are: keep the
   `equiv` checks against a twin generated from the Event-B model, or generate
   RTL from Event-B. Neither was assessed here.
3. Specify an analogue of the mutants for proofs (for example, perturb an
   invariant or a guard and require a PO to fail).
4. Keep `doc.dependencies-first` and the live-set rules as the acceptance test
   for any weave of a Rodin model.

## Environment notes

- `./dev make check`, `./dev make test`, `./dev python3 tools/metrics.py`.
- The pre-push hook runs `make test` and `make check` in a temporary worktree.
  It fails on a shallow clone, because Nix cannot read a missing object; run
  `git fetch --unshallow origin` first.
- `build/design.json` holds the graph; `tools/metrics.py` reports the
  measures.
